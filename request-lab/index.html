Request Lab privacy policy

Effective October 6, 2026

Request Lab is a Chrome extension by Kevin Fitzgerald. It does not collect your data. There is no account, no analytics and no server of ours: what you save stays in your browser on this computer.

What it keeps on your computer

  • Headers: your profiles and rules (header names and values, site names, URL filters and redirect addresses) and which profile the popup shows
  • Mocks: the request addresses, the responses you typed, which ones are on, and your scenarios
  • Environments: your marked sites (address, environment, label, color, project, linked header profile) and how marked sites look
  • The tool you used last, and your license key, if you buy Pro

This lives in the browser's own extension storage. Removing the extension deletes it.

Network

Request Lab has no server and sends nothing about you anywhere. Your header rules and mocks are handed to Chrome, which applies them to requests to the sites you chose; Request Lab never reads requests, responses or page content. On the sites you mark it reads only the page's address, title and tab icon, to add the banner, the title prefix and the colored icon. The only network request it makes itself is checking a Pro license key with Gumroad, when you activate it and every two weeks.

Pro purchases

Pro is sold by Gumroad, which handles the payment and emails your license key. Gumroad's own privacy policy covers that purchase. When you activate a key, Request Lab sends the key and Request Lab's Gumroad product ID to Gumroad's license server (api.gumroad.com) to check it, and checks it again about every two weeks. Nothing else is sent.

Permissions

  • declarativeNetRequestWithHostAccess: Hands the user's header rules (modifyHeaders, redirect) and mocks (a redirect to a data: address holding the saved response, or a block for 'network error') to Chrome, which applies them itself. Request Lab never sees requests, responses or page content. The 'WithHostAccess' variant means a rule only takes effect on sites the user granted, one site at a time, so it shows no install warning.
  • activeTab: When the user clicks the toolbar button (or presses Alt+Shift+E) on a tab, Environments reads that tab's address to show whether it is marked and to offer 'Mark this site' with the address filled in, and Headers reads the tab's ID for tab-only profiles (Pro). Only that tab, only when clicked.
  • scripting: Environments registers its marking script (banner, tab-title prefix, tinted tab icon) for each site the user marked and granted, removes it when the site is removed, and runs it once in the current tab right after the user marks that site.
  • storage: Keeps each tool's data on this computer: header profiles and rules, mocks and scenarios, the marked sites and how they look, the last tool used, and the Pro license.
  • sidePanel: Lets the user keep Request Lab open in Chrome's side panel next to the app they are testing, to switch header profiles, mocks and scenarios while they work.
  • optional:*://*/*: Never asked for as a whole and never at install. Each tool asks for one site when the user saves a rule, a mock or a marked site for it (for example *://*.example.com/* or http://localhost/*), because Chrome only applies request rules, and only lets the marking script run, on sites the extension may access. The settings page lists every site given, with Remove; removing a marked site gives its access back unless a header rule or mock still uses it.
  • optional:https://api.gumroad.com/*: Asked for only when the user activates a Pro license key, to check the key.
  • api.gumroad.com (asked only when you activate a key): to check your Pro license key.

Sharing and selling

Nothing is sold or shared. No data is used for advertising, credit or lending.

Children

Request Lab isn't directed at children under 13 and collects nothing from anyone.
